# DATA SOURCES — canonical provider inventory

Inventory date: **2026-08-22**. Evidence: the dated research files in [research/](research/) (the only
source of external facts in this document) plus the live verification in [V1_AUDIT.md](V1_AUDIT.md) §4 and §8.

## 1. Purpose and how to read this document

This is the registry of record for every external product Cascadia Papsukkal ingests, references or
rejects. Each provider block states what the product is, who issues it, its `source_kind`
([DATA_DOCTRINE.md](DATA_DOCTRINE.md) §2), how it is accessed (mechanism, base URLs, auth, rate limits,
formats), its cadence and latency, spatial/temporal resolution, history depth, missing-data
semantics, quality flags, units, known limitations, licensing, what it feeds, a proposed
`SourceProduct` row (`product_id`, `expected_cadence`, `grace` per [DATA_DOCTRINE.md](DATA_DOCTRINE.md) §5;
ISO 8601 durations; grace values are proposals — ASSUMPTION until a month of ingestion confirms
them), and an evidence line citing the fetched URLs with **FACT** / **INFERENCE** / **OPEN QUESTION**
labels ([CONTEXT.md](CONTEXT.md) conventions). **Rule:** no provider is used by any code path until it
has `DataSource` and `SourceProduct` registry rows ([DOMAIN_MODEL.md](DOMAIN_MODEL.md) §2.2), an adapter
following [../packages/providers/CONTEXT.md](../packages/providers/CONTEXT.md), the eight fixture cases
of [TESTING.md](TESTING.md) §3, and a live canary per [TESTING.md](TESTING.md) §8. Verification status:
the weather, rendering and backend-stack research was independently re-verified on 2026-08-22
(`*.verify.json`; corrections applied below). USGS, NWPS and AWDB were verified live the same day
(V1_AUDIT §8). For every other category, **FACT** is kept only where the research file cites a fetched
URL, and the section header carries an "independent verification pending" note. Status vocabulary:
**verified-live** (fetched live and independently checked), **researched** (fetched URLs, second
verification pending), **web-only** (no machine access found), **open question** (access or terms
unresolved). Provider ids (H1…, W1…, P1…, S1…, R1…, G1…, I1…) are used for cross-reference.

#### H1 · USGS legacy NWIS WaterServices Instantaneous Values — `src:usgs-nwis-iv` · **RETIRED FROM PRODUCTION 2026-08-27** · comparator only

> **The live instantaneous path is H1b (OGC `continuous`) as of 2026-08-27.** Everything below
> remains accurate about the legacy service and is kept because it documents the transport the
> parity comparison was made against — not because anything in production still calls it.
- **What / authority / kind.** Legacy REST service for 15-minute stage/discharge at USGS gauges; USGS Water Data for the Nation; OBSERVED.
- **Access.** GET `https://waterservices.usgs.gov/nwis/iv/?sites=…&parameterCd=00060,00065&period=PT2H|startDT/endDT&format=json|rdb` (FACT); 1–100 sites per call; no key; IPs exceeding "reasonable usage" get HTTP 403 (FACT). Observed 2026-08-22: `startDT/endDT` queries 301-redirect to `https://nwis.waterservices.usgs.gov/nwis/iv/` while `period=` queries answer from the original host — follow redirects (FACT).
- **Cadence / latency.** 15-min values, ~10–15 min behind sensor time (same backend as H2) (FACT). **Resolution / history.** Point gauges; IV from 2007-10-01; some operational parameters limited to 120 days (FACT).
- **Missing / flags / units.** JSON `variable.noDataValue = -999999.0`; values are strings; timestamps in **site-local time with offset** (`2026-08-22T00:45:00.000-07:00`, `timeZoneInfo` PST/PDT); RDB empty cells + `tz_cd` (FACT). Qualifiers `P` provisional, `A` approved, `e` estimated (FACT); Ice/Eqp/Bkw/Dis/Mnt/Rat meanings from search snippets only — the help page 301s to a 404 collection (INFERENCE). Units per pcode: 00060 ft3/s, 00065 ft (FACT).
- **Limitations.** – Decommission: "WaterServices will be decommissioned in early 2027"; blog says first quarter 2027; "no intentional degradation before August 2026"; degradation/blackouts possible in H2 2026 (FACT). – No new parameter codes on NWISWeb since 2026-06-30 (FACT). – Mapping to replacement: iv latest→`latest-continuous`, iv history→`continuous`, dv→`daily`, site→`monitoring-locations`, peak→`peaks` (FACT).
- **License.** US Government work, public domain; provisional-data disclaimer (FACT). **Feeds.** Nothing new; V1 spike adapter only, replaced before Phase 1 exits (ROADMAP).
- **SourceProduct.** `product:usgs-nwis-iv-stage-flow` · cadence PT15M · grace PT75M (doctrine default) · `history_depth` 2007-10-01 · sunset 2027-Q1.
- **Evidence.** FACT https://waterservices.usgs.gov/ · FACT https://waterdata.usgs.gov/blog/api-waterservices-decom/ · FACT https://waterservices.usgs.gov/docs/instantaneous-values/instantaneous-values-details/ · INFERENCE https://help.waterdata.usgs.gov/codes-and-parameters/instantaneous-and-daily-value-status-codes

- **Verified 2026-08-24 (P3 susceptibility).** 78 active WA SNTL (34,719 B); **29** of them fall in the six seed basins by their own HUC12 prefix against the seeded basin HUC8 lists — the basin mapping is derived, never a hardcoded site list. - **Doctrine on how the snow numbers may be used.** `HYDROLOGY.md` §7: **more SWE is not more risk.** SWE and the 14-day precipitation amount are emitted as CONTEXT drivers with `direction="context_not_scored"`, contribute nothing to the susceptibility index, and are labeled as **point-network** statistics (`n` sites and their elevation span), never as a basin mean. In late August every mapped site's WTEQ median is 0.0, so percent-of-median is UNDEFINED and the driver correctly carries no value with that reason — not 0 %, not 100 % (FACT).
- **The percent-of-median estimator, declared (2026-08-26).** `swe_percent_of_median` in `packages/providers/awdb/src/cascade_providers_awdb/normalize.py` ends `mean = sum(c.percent_of_median for c in contributions) / len(contributions)` — a **mean of per-site ratios, computed per basin**, over sites mapped by primary HUC8, with exclusions for absent value, absent median, median ≤ 0 and suspect QC flag (FACT, reproduced from the shipped code path — [research/snow-elevation-verification-2026-08-26.md](research/snow-elevation-verification-2026-08-26.md) §6). It is **not** the pooled ratio-of-sums that circulating critiques of "the 44 % composite" describe, and the platform emits no pooled multi-basin composite at all. Per the `HYDROLOGY.md` §4 percentile rule this is a **POINTWISE aggregate** of point observations and must be labelled as one — never as "the basin snowpack" and never as a basin percentile. The two estimators are not interchangeable: on 2025-12-08 in the Puyallup-White they differ by more than a factor of two (**48.7 %** ratio-of-sums against **23.3 %** mean-of-ratios); ratio-of-sums asks *"what fraction of normal basin storage is present"*, mean-of-ratios asks *"how anomalous is the typical site"*. This is a **declaration, not an experiment** — no measurement settles it, so the choice belongs in the method id and `n` plus the exclusions (`ContextResult.excluded`) must render beside every value (`CONTRADICTION_REGISTER.md` X16).

## 5. Cross-cutting pitfalls

Every item below is enforced by an adapter fixture case (TESTING.md §3 case 6/8) or a canary, not by convention.

### 5.1 Units

| Pitfall | Where | Rule |
|---|---|---|
| **kcfs vs cfs** | NWPS `stageflow.secondaryUnits` = kcfs while `flood.flowUnits` = cfs and ratings are cfs; AUBW1/WRAW1 thresholds are cfs (H3); NWRFC tables mix cfs/kcfs (H5, R4) | store native unit per value; never compare without `pint` conversion (DATA_DOCTRINE §6) |
| inches vs mm | USGS 00045 and SNOTEL in; NWS API `wmoUnit:mm`; MRMS mm; Stage IV GRIB kg m⁻² but NWPS NetCDF inches; WPC GIS inches, GRIB kg m⁻² (INFERENCE) | canonical mm; display both |
| kg m⁻² ≡ mm liquid | NBM/HRRR/GFS APCP, NWM `SNEQV`, NLDAS soil moisture (kg m⁻² per layer) | registry-pinned definition `kg m-2 = mm` for water equivalent only |
| ASNOW in metres | HRRR/NBM ASNOW m; NBM thresholds 0.0254 m = 1 in (W2) | convert at ingest; label snowfall vs SWE |
| acre-feet vs m³ vs KAF vs billions of gallons | USACE `Stor` ac-ft; NWRFC `LS` **kaf**; SPU synopsis billions of gallons; NID ac-ft | canonical m³; `acre_foot` and `kaf` registry units |
| English-only APIs | AWDB (in, °F, % VWC); USACE `/timeseries` returns ft while the catalog declares SI (R1) | always pass `unit` explicitly where supported |
| SNODAS scale factors and int16 | SWE m×1000, melt m×100000, precip kg m⁻²×10; saturation at 32.767 m | decode with the product-code table, flag saturated cells |
| Soil moisture semantics | SMAP/NWM m³ m⁻³; SNOTEL SMS % volumetric; AgWeatherNet kPa (matric potential) | separate variable ids; never fuse kPa with VWC |

### 5.3 Time zones, day boundaries and epochs

| Provider | Behaviour | Rule |
|---|---|---|
| USGS legacy IV | site-local timestamps with offset (`-07:00` PDT / `-08:00` PST), `timeZoneInfo`, RDB `tz_cd` | convert to UTC, keep zone as metadata |
| USGS OGC API | RFC3339 UTC; daily `time` is a date | daily values stored with provider day (site local) |
| AWDB SNOTEL | PST year-round (`dataTimeZone −8`, no DST); DAILY = 00:00 PST reading; `periodRef=END` dates it D, `START` dates it D+1 | always pass `periodRef`; store `day_boundary = 00:00 PST` (DATA_DOCTRINE §3) |
| NWPS / HEFS | UTC `Z`; gauge `timeZone 'PST8PDT'`; HEFS `forecast_datetime` 12Z | `issued_at` = `issuedTime`; `available_at` ≥ `generatedTime` |
| USACE CDA | `[epoch_ms, value, quality]`; `timezone=UTC` param; A2W ISO strings | parse epoch ms as UTC |
| NWM | "minutes since 1970-01-01 00:00:00 UTC" | integer minutes → UTC |
| SNODAS | SWE snapshots 06:00 UTC; fluxes 06–06 UTC | `valid_time` 06Z, not the file date |
| NWRFC | CHPS T0 12Z; text "Issued 08:05 PDT" | store both; `issued_at` in UTC |
| NWS API / MRMS / GRIB | UTC; GRIB accumulation windows explicit (`18-24 hour acc`, `300-315 min acc`) | window start/end on every accumulation value |

**A site-local day boundary is only as good as the zone key that computes it.** `station.time_zone`
must be the CANONICAL IANA name (`America/Los_Angeles`), never a provider's spelling: NWPS reports
`timeZone 'PST8PDT'` and USGS RDB reports `tz_cd PST`, and neither is resolvable in the deployment
image, which ships `tzdata` without `tzdata-legacy`. A key that will not resolve degrades every
daily value onto midnight UTC under the flag `day_boundary_assumed_utc` — measured in production
2026-08-24 to 08-27. The seed refuses such a key now ([ADR-0017](adr/ADR-0017-canonical-iana-time-zones-in-the-seed.md)).
