# V1 Audit — the Emergent prototype

Audited 2026-08-22 against the full source of `crl33/cascade-oracle` (commit `06a1c69`,
imported at `v1/`). Every claim below was checked in the code; where an external fact
mattered, it was verified live against the provider API on the audit date
(`docs/research/v1-live-verification-2026-08-22.json`).

Verdict in one line: **V1 is a credible product prototype with real domain knowledge and a
good trust doctrine, sitting on an architecture that cannot become the platform. Preserve the
knowledge; rebuild the system.**

## 1. What V1 is

| Aspect | Finding |
|---|---|
| Origin | Generated by Emergent.sh (`.emergent/emergent.yml`, job created 2026-05-02); single squash commit "Auto-generated changes" — no development history |
| Backend | FastAPI 0.110 + Motor/MongoDB; 12 Python files, ≈1,300 lines of domain code (`v1/backend/lib/`) |
| Frontend | React 19 on CRA 5 + CRACO, JavaScript (no TS), Tailwind 3, 44 generated shadcn/Radix components (≈6 used), Framer Motion, Recharts |
| Providers | USGS NWIS IV (`usgs.py`), NOAA NWPS gauge categories (`nwps.py`), NRCS AWDB SNOTEL WTEQ (`snotel.py`) |

| Persistence | Mongo collections `co_stations` (config), `co_snapshots` (latest snapshot per station, upserted), `co_meta` (last refresh) — **no history** |
| Tests | `tests/__init__.py` is the only committed test module (empty). `backend_test.py` is a live script against a dead Emergent preview URL |
| Docs | `plan.md` (phased plan), `design_guidelines.md` (JSON design system), `.emergent/summary.txt` (agent self-report), `test_result.md` (protocol header only), three `test_reports/iteration_*.json` (agent-written) |

## 3. Architectural findings (independently verified)

**A. User requests drive data acquisition — confirmed.** `GET /api/stations` calls
`_ensure_fresh_all()` which, on a cache miss or a >300 s snapshot age, performs live USGS,
NWPS and AWDB calls inside the request (`v1/backend/server.py:111-125`, `198-207`). Nobody
viewing the dashboard ⇒ no data collected.

**B. History is not a dataset — confirmed.** `upsert_snapshot` overwrites one document per
station (`v1/backend/lib/cache.py:92-98`). The 24 h series inside each snapshot is the USGS
response window, not stored history; the `history` collection in `plan.md` §2 was never built.
There is no time series of anything V1 computed.

**C. MongoDB as primary store — confirmed wrong fit.** Every V1 query is by exact key; nothing
uses document flexibility. Everything the platform needs (basins, reaches, gauges,
observations, forecasts, thresholds, events) is relational, temporal and geospatial. See
ADR-0001.

**D. Generated/legacy frontend — confirmed.** CRA 5 (`react-scripts`), CRACO, JavaScript,
`@emergentbase/visual-edits` loaded from a tarball URL in dev, Emergent debug CSS hooks
(`index.css` `[data-debug-wrapper]`), `package.json` lists react-hook-form, zod, embla,
input-otp, cmdk, react-day-picker, vaul, next-themes, react-resizable-panels — none used by
domain code.

**E. Premature frozen contract — confirmed.** `PrecursorKind` is a closed `Literal` of five
names; `BasinPrecursors` has one field per name. Adding "rain 6 h" or "freezing level" means a
schema change and a frontend change.

**F. Process-local caches — confirmed.** `_CACHE` and `_LAST_LAYER_STATUS` are module globals
(`precursors.py:31-34`); `GET /api/system/precursors` reports whichever worker answered.

**G. Testing quality — confirmed, worse than described.** See §6.

Additional findings not in the brief:

- **H. Unauthenticated, unthrottled upstream triggers.** `POST /api/refresh` and
  `POST /api/stations/{id}/refresh` (`server.py:231-256`) let any caller make Cascade Oracle
  hammer USGS/NOAA/NRCS. `CORSMiddleware(allow_origins="*", allow_credentials=True)`
  (`server.py:261-267`) is an insecure combination.
- **I. Third-party scripts and analytics in the page.** `frontend/public/index.html` loads
  `https://assets.emergent.sh/scripts/emergent-main.js`, a PostHog snippet with a hard-coded
  project key and `session_recording` enabled (including cross-origin iframes), and a
  "Made with Emergent" badge. Every V1 user session was recorded to a third party.
- **J. Dependency sprawl.** `backend/requirements.txt` pins 27 packages; the app imports
  fastapi, uvicorn, motor, pydantic, httpx (not even listed!), python-dotenv. Unused: boto3,
  requests-oauthlib, cryptography, pyjwt, bcrypt, passlib, python-jose (known CVEs),
  pandas, numpy, jq, typer, emergentintegrations, email-validator, python-multipart.
- **K. `httpx` is imported but absent from `requirements.txt`** — the app only ran because
  the Emergent image had it.
- **L. Scientific logic in React.** `RiverGaugeCard` computes a 24 h stage trend from the
  series; `PrecursorPanel.parseTrend` regex-parses backend prose to derive trend direction;
  `confidenceBucket` thresholds live in the UI. `FilterBar` fetches `/system/basins` with raw
  axios on mount (component-driven fetching).
- **M. Mislabeled provenance in the UI.** The "Observed data" section badges USGS
  observations with the `official_nwps` SourceBadge (`StationDetailDialog.js`, observed
  section). Hero copy "Observed and modeled signals stable" — there are no modeled signals.
  `PhaseRoadmap` and `SystemDisclaimer` hard-code "Phase 1" while the backend reports 2A.
- **N. Timestamp comparison by string.** USGS `dateTime` strings carry local offsets
  (`-07:00`/`-08:00`); `usgs.py:101-103` orders them lexicographically. Across the November
  DST change — flood season — ordering can be wrong. SNOTEL daily values are stamped
  `T00:00:00+00:00` although AWDB reports `dataTimeZone: -8`.
- **O. Qualifiers ignored.** Every current USGS value carries qualifier `P` (provisional);
  `usgs.py` drops qualifiers entirely. Approved/provisional/estimated/ice-affected are
  indistinguishable downstream.

## 4. Scientific findings

**4.1 Green and White River thresholds exist — V1 could not read them.** Live NWPS (2026-08-22):

| LID | Gauge | action | minor | moderate | major | Unit |
|---|---|---|---|---|---|---|
| AUBW1 | Green River near Auburn | 6,000 | 9,000 | 12,000 | 14,000 | **cfs (flow)**; stage −9999 |
| WRAW1 | White River at R St., Auburn | 5,500 | 7,500 | 10,000 | 12,000 | **cfs (flow)**; stage −9999 |

NWPS's primary observed series for both is "River Discharge" in **kcfs**. `nwps.py:22-37`
reads only `stage`, sees −9999, and reports `thresholds_unavailable`. V1's station notes
attribute this to "non-standard gauge datums"; the real reason is that NWS defines flood
categories by flow on these regulated reaches (below Howard Hanson and Mud Mountain dams).
Consequence: two of six stations were permanently "unknown" for a parser reason while being
presented as a doctrine outcome.

**4.2 Every V1 fallback threshold is wrong.** Compared with official NWPS categories:

| Station | V1 fallback (ft) | NWPS official (ft) |
|---|---|---|
| Cedar at Renton | 9 / 11 / 13 / 15 | 10.4 / 13 / 14.5 / 16 |
| Snoqualmie nr Carnation | 54 / 56 / 58 / 60 | 50.7 / 54 / 56 / 58 |
| Skagit nr Mount Vernon | 25 / 28 / 32 / 35 | 23.5 / 28 / 30 / 32 |
| Nooksack at Ferndale | 12 / 14 / 16 / 18 ("validated NWS thresholds" per `poc_hydro.py:84`) | 15 / 18 / 20.5 / 23 |

They were gated off by `fallback_validated: False`, so no wrong category was ever shown —
which is precisely why the gate is the part worth keeping. V2 removes configured thresholds
from the risk path entirely (`DATA_DOCTRINE.md` §7).

**4.3 NWPS is far richer than V1 used.** The gauge resource carries official forecasts
(`/stageflow`: issued time, 31–40 six-hourly points, stage+flow), `upstreamLid`/`downstreamLid`
(routing topology), `reachId` (NWM feature), `flood.crests.historic` (crest records with
flags), `flood.impacts` (stage-keyed impact statements, including Skagit County "Phase"
levels), `datums` (NGVD29 for RNTW1/MVEW1/AUBW1/WRAW1, NAVD88 for CRNW1/NKSW1),
`forecastReliability`, `ObservedFloodCategory`/`ForecastFloodCategory`, `inundation`,
`rfc` (NWRFC) and `wfo` (SEW). V1's footer "Forecast layer not yet active" described a
choice, not a data gap.

**4.4 One SNOTEL station per basin is not a basin snow state.** V1 says so itself
("representative upstream signal only"), correctly. Two refinements: (a) NRCS lists Harts Pass
(6,490 ft) in HUC12 171100050501 "Upper Canyon Creek" (Upper Skagit, draining toward Ross Lake —
a regulated reservoir) but its `associatedHucs` are Methow/Pasayten units and the site sits on the
crest (FACT, `docs/research/snow-and-soil-state.json`), so it is an east-crest headwater proxy for
the *controlled* upper Skagit, not a maritime index for Mount Vernon's response, which is dominated
by the unregulated Sauk (Marten Ridge, Thunder Basin, Beaver Pass, Brown Top, Rainy Pass, Swamp
Creek and Decline Creek carry that signal); (b) AWDB supports `centralTendencyType=MEDIAN` and returns per-value
`median` with `qcFlag`/`qaFlag` — V1's "percent-of-normal needs more research" was a
one-parameter change.

**4.5 Datums.** USGS reports the Mount Vernon gauge altitude in NAVD88 (3.8 ft) while NWPS
lists NGVD29 among the site's datums; both stages are relative to gauge datum, so the numbers
V1 compared were compatible — but V1 never recorded which datum a threshold belongs to. V2
stores datum on both observation series and thresholds and refuses comparisons across
unrecorded datums.

**4.6 "Confidence" numbers were invented.** `snotel.py:71-78` maps high/medium/low to
0.85/0.65/0.45 and subtracts 0.30 when stale. Presented as "Confidence • High" in the UI.
V2 shows mapping quality as a labeled category and reserves numeric confidence for calibrated
quantities (`DATA_DOCTRINE.md` §9).

**4.7 Stale thresholds were plausible but arbitrary.** 90 min for USGS, 3 days for SNOTEL,
15 min in the design doc — three different numbers for one concept. V2 defines staleness per
product from its cadence (`DATA_DOCTRINE.md` §5).

## 5. Security findings

| # | Finding | Severity | V2 response |
|---|---|---|---|
| S1 | Unauthenticated `POST /refresh` endpoints trigger upstream fetches | High (abuse of third-party quotas, cost) | No request-path ingestion; admin actions authenticated + rate-limited |
| S2 | Third-party remote script + PostHog session recording with hard-coded key | High (privacy, supply chain) | No third-party scripts; first-party opt-in telemetry only |
| S3 | `CORS allow_origins=* + allow_credentials=True` | Medium | Explicit allowlist |
| S4 | Dependency from non-registry tarball (`assets.emergent.sh`) | Medium (supply chain) | Registry-only, lockfiles, audit in CI |
| S5 | 20+ unused Python deps incl. `python-jose` (CVE-2024-33663/33664) | Medium | Minimal, pinned, audited |
| S6 | No input limits on any endpoint (none take input today) | Low now, High later | Limits designed in (`vibesec` addendum §3) |
| S7 | `.gitignore` references `memory/test_credentials.md` | Informational | No credentials in repo; secret scanning in CI |

## 6. Testing claims vs evidence

- Committed tests: **zero**. `tests/__init__.py` is empty.
- `backend_test.py` targets `https://river-command.preview.emergentagent.com/api` and
  asserts on live conditions: `snowpack_active == True`, `precursors.available == True` for
  all six stations, SWE ≥ 0 (`backend_test.py:586-605`, `663-722`). The suite passes only when
  NRCS has data for every station — a weather-dependent test.
- The file contains a dead `test_system_status` expecting `phase == 1` alongside
  `test_phase_2a_system_status` expecting `phase == 2` — the earlier assertion was never
  deleted, just unlisted from `run_all_tests`.
- "Frontend 22/22 tests passed" has no corresponding code anywhere in the repository; the
  reports describe an agent clicking through a preview.
- `.emergent/summary.txt`: "Areas that need refactoring: None at this time. Architecture is
  extremely modular." This audit disagrees on every point above.

V2's testing hierarchy (`TESTING.md`) makes these failure modes structurally impossible:
fixtures for deterministic tests, live canaries quarantined and non-blocking, and no
"tested" claim without a committed test.

## 7. Useful intellectual property to carry forward

1. The six-basin starting set and its identifiers.
2. The principle "configured ≠ official; unvalidated ⇒ UNKNOWN" and the explicit source taxonomy.
3. The precursor/risk separation (becomes the three-surface model).
4. The honest disclosure pattern: `mapping_note`, "representative signal only", error lists.
5. The design system: deep-navy canvas, cyan→amber→red tension ladder, restrained motion,
   source badges adjacent to state badges, reduced-motion rule, `data-testid` discipline.
6. The staged, claims-earned product narrative (keep the spirit of `/roadmap`).
7. Provider API shape knowledge (USGS IV JSON layout, NWPS categories, AWDB batching).

## 8. Live verification summary (2026-08-22)

- USGS NWIS IV: all six sites return 00060/00065 with qualifier `P`; `noDataValue` −999999.
- USGS new OGC API (`api.waterdata.usgs.gov/ogcapi/v0`) is live with `continuous`,
  `latest-continuous`, `daily`, `monitoring-locations`, `peaks`, `time-series-metadata`
  collections; `monitoring-locations` exposes `vertical_datum` (NAVD88), `altitude`,
  `drainage_area` (Skagit nr Mount Vernon: 3,093 mi²), `hydrologic_unit_code`.
- NWPS: all six LIDs resolve, RFC = NWRFC, WFO = SEW; forecasts issued 2026-08-21 ~15:05Z
  for all six; Green/White categories in flow (§4.1).
- NWPS historic crests for MVEW1 list **2025-12-12 08:15Z, 37.73 ft, 132,717 cfs
  (preliminary)** as the record of record — above 1990-11-25 (37.37 ft) and 1995-11-30
  (37.34 ft). This is Event Zero's anchor observation.
- AWDB: six SNOTEL triplets resolve with HUCs matching V1; elements available include
  WTEQ, SNWD, PREC, PRCP, TOBS, TAVG, SMS (soil moisture), STO (soil temperature);
  `centralTendencyType=MEDIAN` works. Harts Pass SWE 2025-12-01→07: 14.0→18.4 in
  (median 11.7→13.2) — above median going into the event.
